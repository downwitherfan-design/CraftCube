## 1. Semantics

One immutable record per release-channel artifact set, **generated by CI after signing, never hand-edited**. It answers: which commit, which content, which schema versions, which validators, which checksums, which signing identity (public fingerprint only), which optional-layer flags. It contains **no secrets and no personal data** (the `builder` field names a CI system and run identifier, never a person).

It is embedded read-only in the build (player-inaccessible, support-readable) and stored alongside the artifact with the same retention.

```json

  "app_version": "0.1.0-internal",
  "build_number": 1,
  "content_version": "0.1.0",
  "content_digest": { "algorithm": "sha256", "hex": "<64 hex chars>" },
  "schema_versions": {
    "save": "0.0.0",
    "ruleset": "0.0.0",
    "content": "0.0.0",
    "event": "0.0.0"
  },
  "git": { "commit": "<40 hex chars>", "tag": "v0.1.0+1", "branch": "integration" },

  "build_timestamp_utc": "2026-01-01T00:00:00Z",
  "builder": { "system": "github-actions", "run_id": "<opaque string>" },
```

### Field rules

| Field | Type | Rule |
|---|---|---|
| `schema` | string | MUST equal `"BuildProvenance"`. |
| `schema_version` | string | semver `MAJOR.MINOR.PATCH`. |
| `fixture_kind` | enum | `PRODUCTION` \| `MOCK`. MOCK records MUST also carry a `_mock_notice` string and MUST NOT be reachable from shipped content roots (`RG-010`). |
| `app_version` | string | semver with optional pre-release `-internal` \| `-alpha` \| `-beta` \| `-rc.N`. |
| `build_number` | integer ≥ 1 | Monotonic per channel; CI-assigned. |
| `content_version` | string | semver. |
| `content_digest` | object | `algorithm` ∈ {`sha256`}; `hex` is exactly 64 lowercase hex chars. |
| `schema_versions` | object | Keys `save`, `ruleset`, `content`, `event` all required; each semver. Values are **recorded, not owned** by AI-12 (owners: AI-02 save/ruleset, AI-03 content schema, AI-13 event). `0.0.0` is the explicit "not yet released" value, never omitted. |
| `git.commit` | string | exactly 40 lowercase hex. `git.tag` MAY be empty string for non-tagged internal builds; MUST be non-empty for alpha/beta/production. `git.branch` non-empty. |
| `channel_id` | string | MUST match `^release\.channel\.(internal|alpha|beta|production)$` (Direction Lock §6, DRAFT). |
| `build_timestamp_utc` | string | RFC 3339 UTC with trailing `Z`. |
| `builder.system` | string | non-empty; a system name, never a personal identifier. `builder.run_id` non-empty opaque string. |
| `unity_version` | string | non-empty; copied from the build tool's own report, never typed. |
| `feature_flags` | object | Keys `telemetry`, `remote_content`, `leaderboards` all required booleans. |
| `artifacts` | array ≥ 1 | Each: `kind` ∈ {`apk`,`aab`,`symbols`,`mapping`}; `file_name` non-empty; `size_bytes` integer ≥ 0; `checksum` as `content_digest`. At least one `apk` or `aab`. |
| `signing_identity_fingerprint` | object | Certificate fingerprint only (`algorithm` ∈ {`sha256`}, 64 hex). **Never key material.** Validator rejects any key containing `password`, `secret`, `keystore`, `private` anywhere in the record (`RG-011` in-record scan). |
| `validators` | array ≥ 1 | Each: `rg_id` matches `^RG-[0-9]{3}$`, `validator_id` non-empty, `validator_version` semver, `exit_code` integer, `findings` integer ≥ 0. **A record is valid only if every listed `exit_code` is 0** and the set contains at least `RG-010`, `RG-011`, `RG-012`. Channel-specific required sets are bound in Phase 01 (`RELEASE_VALIDATION_GATE_POLICY.md` §3). |

## 3. Failure behaviour

- A missing or invalid provenance record → Gate F FAIL; artifact must not be promoted to any channel.
- A record whose `content_digest` does not match a recomputation over the shipped content roots → FAIL (tamper/stale-content detection).
- A record listing a validator with non-zero `exit_code` → FAIL (a red validator can never be "recorded and shipped").

## 4. Determinism

Given the same commit, content bytes, channel and build counter value, every field except `build_timestamp_utc`, `builder.run_id` and the artifact checksums (which depend on signing/packaging bytes) is byte-identical across runs. Reproducibility comparisons (Direction Lock §12) therefore exclude exactly those three fields and compare all others.

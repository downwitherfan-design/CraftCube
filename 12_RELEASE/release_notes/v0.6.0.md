## What's in this build

CC-PROD-060 — runtime recovery and real gameplay presentation. This build fixes the defect
that made the game look broken on a fresh launch and rebuilds the cube's rendered presence.

- **Defect fixed: the cube was invisible (the "black screen" incident).** `CubeView` built its
  dark core box at half-size `1.0` (spanning ±0.98) while the coloured facelet shell only
  reaches `1 - TILE_GAP/n` (~0.92–0.96). The core therefore enclosed the tiles, won the depth
  test and rendered the whole cube as a solid dark slab over the sky — every level, every
  topology, no cube and no legible contrast. The core is now built strictly inside the facelet
  shell (`outer - CORE_INSET`) and the larger edge frame that also enclosed the tiles is gone.
  Verified with real Xvfb/OpenGL captures: the cube now renders with visible amber/white
  facelets in both `App.tscn` and `Main.tscn`, centred and prominent (~60% of the screen width).
- **Defect fixed: HUD guidance covered the cube.** The gameplay HUD's middle spacer was an
  expanding control, so the scrolling guidance column (readiness / resonance / onboarding)
  rendered text directly over the cube band on a normal portrait phone. A fixed-height, empty
  cube band now reserves the camera's framing area; guidance sits below the cube. Pixel
  analysis confirms no bright text remains inside the cube band.
- **Regression coverage.** New `_test_cube_core_occlusion` asserts, for 2×2/3×3/4×4, that the
  dark core is strictly inside the facelet shell and never reaches the rendered tile surface,
  so this class of defect cannot silently return.

The application entry flow (title/menu, campaign map, journal, settings, results), the six-level
Chapter 01 campaign, mastery ratings, save migration and the Nox companion interaction from the
previous epic are unchanged and still pass. All changes are backward compatible; an existing
save is loaded unchanged.

## Known limitations

- Debug-signed with a development keystore; **not** a production/store release.
- No physical Android device was used; the APK was built and statically verified. Rendered
  evidence was captured through a Mesa llvmpipe software-GL path under Xvfb — it is **not** a
  device-GPU benchmark.

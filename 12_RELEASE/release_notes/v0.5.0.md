## What's in this build

EPIC 0.5 — Chapter One Gold Slice: a single, coherent visual identity ("The Living Mineral
Garden") across the world, the cube and the application shell, plus the highest-impact runtime
defect on the branch.

- **Shared art direction (Milestone A).** A new `CraftPalette` (`game/scripts/presentation/
  palette.gd`) is the one source for every colour: the six cube face colours, the companion
  body/glow, the per-ward accents, and the world's ground/sky tones. The world, the cube and
  the menu chrome all read from it, so the product looks like one game instead of three.
- **Living world presentation (Milestone A/C).** The world is now layered rather than a single
  slab: a dark plinth, a raised garden disc with a lit rim, and a stepping-stone path that
  heals (teal) one stone at a time as levels are solved. Ward stones take their accent from the
  palette, and Nox gains two foot nubs plus a restrained idle bob/turn and a `nox_react_now()`
  attention gesture; reduced motion holds it still. All primitives — no external assets.
- **Cube presentation (Milestone B).** Face colours come from the palette, tiles are separated
  by a visible gap, and the cube gains a dark inner core and a thin edge frame, so it reads as
  separated tiles rather than a flat slab. The 3x3 topology (levels 4-6) renders correctly with
  no logical/rendered divergence.
- **Application shell identity (Milestone D).** The home screen backdrop is now a procedural
  vertical gradient (built-in `GradientTexture2D`, asset-free) with a face-colour emblem under
  the title, so the shell matches the world's art direction.
- **Defect fixed: the shell covered the 3D world.** The application shell drew an opaque
  full-screen backdrop at all times, so every gameplay frame was ~97% pure black — the rendered
  cube and world were hidden behind the menu chrome. The backdrop is now hidden while gameplay
  is on screen and restored on menus. Measured after the fix: the world-sigil frame went from
  3.1% to 41.4% non-black pixels; the cube zone shows 25-38 distinct saturated face colours.
- **Runtime-quality evidence (Milestone E).** A new `game/tests/runtime_quality.gd` records the
  procedural-only budget (gameplay 145 nodes / 83 meshes / 51 materials; app 216 nodes /
  83 meshes) and a steady-state frame-time sample.

All changes are backward compatible; an existing save is loaded unchanged.

## Verification

- Domain test suite: `godot --headless --path game --script res://tests/run_tests.gd` → 876 passed, 0 failed.
- Android pipeline: `bash game/ci/build_android.sh` → `CI: PASS`.
- Rendered evidence (Xvfb/GL, 720x1280): `docs/evidence/screenshots/session15_*.png`
  (title, chapter map, settings, 3x3 cube and orbit).
- Version consistency verified by `game/ci/validate_version.py`.

## Known limitations

- Debug-signed with a development keystore; **not** a production/store release.
- No physical Android device was used; the APK was built and statically verified. The frame-time
  figure above is a Mesa llvmpipe software-GL path under Xvfb — it is **not** a device-GPU
  benchmark.
- The APK is produced by the pipeline and attached as a release asset; it is not committed to source.

## Policy

See `12_RELEASE/ANDROID_RELEASE_POLICY.md`. Every release must produce a versioned APK
attached to a GitHub Release; an ordinary CI pass is not the release deliverable.

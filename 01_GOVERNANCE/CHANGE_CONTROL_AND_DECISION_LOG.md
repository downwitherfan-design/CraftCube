# Change Control & Decision Log

Every breaking or cross-track change must record:
- decision ID;
- affected contract/schema/API/event/asset;
- old version → new version;
- reason;
- impact;
- affected accounts;
- compatibility/migration plan;
- tests proving the change;
- rollback plan;
- approver/integration owner.

Prefer additive changes. Deprecate before removal when practical.
